## 这节课教的流程

1. **Fork**：把老师的仓库复制一份到自己账号下
2. **Clone → 开分支**：`docs/xxx` 这种小分支，别直接在 main 上改
3. **改一个点**：老师示范的是 README 里加两行 `docker-compose up -d postgres`
4. **commit + push**：提交信息一句话说清改了什么
5. **发 PR**：标题=改了什么，正文=为什么改、怎么验证
6. **等 review，合并**

要点：一次 PR 只做一件事；README 是这类项目的「入口文档」，谁都从它开始读。

## 我们踩过的坑

- **撞段落**：PR #2 和 #3 都在 README 的启动章节附近，hunk 相邻。不冲突，但同一文件两条 PR 并行容易互相 rebase，先对齐再改。
- **5555 vs 5432**：`backend/app/core/config.py` 默认 `localhost:5555`，compose 映射的是 `5432`，不建 `.env` 就连接失败。
- **seed 要等就绪**：`docker-compose up -d postgres` 返回时数据库可能还在初始化，直接 `python -m app.db.seed` 会 connection refused。

## 我给自己定的规矩（仙人版）

1. **老师仓库只读**：不改文件、不提 PR、不留评论；要写只写自己 fork 的分支。
2. **只追加，不删改**：原文件保持原样，要补说明就新加一节/新文件；`main` 始终与上游一致。
3. **不破坏历史**：不 force push、不删别人分支、不重写已推送的提交。
4. **动完留账本**：分支名、提交信息写明内容；每次给本人一句话说明改了什么、在哪、怎么撤。

撤回方式很简单：本地删分支即可，远端分支删掉或 PR 关闭，上游什么都没有发生。
